## Reusable contract

1. **One task surface:** list/card → Task details → Edit task draft → Save → Details. Search, capture, profile and reschedule use the same named frame. Background controls are inert; focus enters, stays inside and returns to the opener. Header, scrollable body and primary actions stay within the visible viewport.
2. **Draft ownership:** title, status, project, Plan for and Due by are core fields. More details reveals priority, energy, estimate, description, notes and tags. Typing does not write. Save validates and sends one patch; errors retain values. Creation and known-task commands prevent repeated submission while pending.
3. **Honest outcomes:** authoritative success is announced; completion offers Undo, which reopens rather than promising restoration of every prior lifecycle field. Failed actions remain recoverable. A lost response, malformed success or legacy queue receipt is uncertain: refresh/reconcile before another write. Offline copy promises retained drafts and explicit retry, not automatic mobile synchronization.
4. **Dates:** Plan for is an instant; Due by is a date explicitly selected through the end of the device-local day. Preserve existing exact timestamps unless that field is changed. Legacy UTC-midnight deadlines retain their named day; “Use end of this day” is an explicit normalization. Validate planned time ≤ deadline. The browser uses the device timezone because account timezone is unavailable in its user DTO; do not claim account/device parity.
5. **Back and dismissal:** clean editor returns to Details; Details returns to its list/project. Dirty capture/editor/reschedule offers Keep editing or Discard. Close, Cancel, backdrop, Escape and browser Back consult the same active owner. Pending saves cannot be dismissed. Successful all-close returns to the list; obsolete Forward cannot reopen a saved/discarded draft. Reload restores tab/project/scroll preferences, clears transient sheets and does not persist unsaved drafts. Old same-URL entries may still consume additional Back presses after reload.
6. **List ownership:** separate completion and details buttons; actions stay available by tap. Swipes lock to a direction, cancel safely and suppress accidental clicks. The fixed-height shell content owns scrolling. Restore a view after its initial data arrives; continue recording user scroll during background refresh without jumping to the previous offset. Task/project/Focus reads preserve current data and expose failures/Retry.

Keep Fold's coral mark, parchment/ink palette, type, illustrations and tarot identity. **Keep Focus cards and compact Today/Everything/project lists; hide nothing.** Measured interaction defects justify repair. Whether a shorter agenda preview or denser Focus layout is preferable remains a later user/product decision, not a result proven by correctness tests.

## Smallest coherent implementation phases

1. **Frame and touch ownership:** common modal, active surface, body/handle separation and composed touch regression. This is a diagnostic milestone, not release acceptance while P1 data issues remain.
2. **Draft and command reliability:** explicit saves, full fields, response/uncertainty handling, serialized writes, dates, complete/undo, offline policy and retained failure recovery. Gate on latency, duplicate actions, fresh reads and reload.
3. **Navigation and device qualification:** gesture/scroller ownership, Back/project/tab/scroll restoration, refresh/Focus reconciliation and bounded card-control repairs. Gate on Chromium/WebKit touch and then physical-iPhone acceptance. One coherent draft carries these phases together; merge/deploy remain separate decisions.

## Focus cache and creation recovery limits

The real Focus GET may return an AI brief cached for four hours; the refresh POST starts a background rebuild. Task references are reconciled against current task records before becoming actionable. AI narrative retains its generated-at/cache status rather than implying newly generated insight. An ambiguous creation has no reliable request identity: the retained capture draft can refresh and show possible existing matches, but a matching title is not proof of which request created it, and no automatic replay is permitted. Legacy queue triggers are coalesced within a running worker; durable exactly-once replay across worker restarts is outside this bounded change.
